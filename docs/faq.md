# Вопросы и ответы

## Кит и песочница

### Песочница разрешает java.net. Почему нужен мост?

Клиент разрешает только официальные API. `java.net` в скрипте — это загрузка, которая падает с `references blocked symbol`. Мост работает вне песочницы: скрипт шлёт запрос через настройки, мост выполняет его в сети. Ни один запрещённый символ в `.kts` не появляется.

### Можно ли обойтись без моста?

Нет. Внутри скрипта нет ни сокетов, ни HTTP-клиента — это ограничение клиента, а не кита.

### Нужен ли клиент Nursultan, если мост работает сам по себе?

Нужен: мост опрашивает именно запущенный клиент через MCP. Без клиента мост пишет `MCP недоступен` и ждёт.

## Установка

### Где взять ссылку MCP?

Клиент → вкладка **Scripts** → кнопка **MCP** → **Enabled** → **Copy link**. Ссылка вида `http://127.0.0.1:<порт>/mcp/<токен>`, вставляется в `mcpLink` в bridge.json.

### Порт изменился, мост не подключается

Порт и токен сохраняются между запусками клиента, но могут смениться. Скопируйте ссылку заново и обновите `mcpLink`. Проверка: `python bridge/nursultan_bridge.py --check`.

### Мост работает без прав администратора?

Да. Ни реестра, ни служб, ни системных папок мост не трогает.

### Как запускать мост вместе с игрой?

Ярлык `nursultan-internet-bridge.exe` в папку `shell:startup`, либо ручной запуск перед игрой.

## Запросы

### Сколько запросов одновременно?

Один на скрипт: один слот `net.req`. Несколько скриптов работают параллельно — каждый со своим слотом.

### Почему ответ не мгновенный?

Тик 50 мс + опрос моста 150 мс + время запроса. Реалистично — от 1,5 с. Языковые модели отвечают 1–15 с.

### Можно ли ждать ответ внутри обработчика?

Нет: обработчик ограничен 250 мс, спать и крутить циклы нельзя. Ожидание — в тиках через `netTick()` и проверку `netReady`.

### Что такое `netCode 0`?

Ошибка моста: неверный конверт, ключ не найден, хост вне allowlist, приватная сеть, таймаут, невалидный JSON для jsonpath. Текст ошибки — в `netBody` и в `requests.log`.

### Ответ читается дважды?

Сбрасывайте `netReady = false` сразу после чтения — один ответ обрабатывается один раз.

### Запрос теряется, `netSend` возвращает -1?

Слот занят предыдущим запросом. Отправляйте только после `netBusy() == false`.

## Ключи и безопасность

### Можно ли вписать ключ прямо в скрипт?

Нет: файл утечёт при передаче. Только `keyref` на имя из `secrets` в bridge.json.

### Что увидит человек, получивший мой скрипт?

Файл скрипта без ключей. Без своего заполненного `bridge.json` он получит `code 0` и текст `ключ ... не найден`.

### Мост можно использовать из интернета?

Нет: MCP слушает `127.0.0.1`, мост — исходящие клиент. Входящих соединений нет.

### Что попадает в requests.log?

Хост, метод, статус, время, размер каждого запроса. Значения ключей — нет.

## Форматы

### Почему запрос и ответ — не JSON?

В песочнице нет JSON-парсера. Текст читают обе стороны без библиотек, а поля вырезает мост по директиве `jsonpath`.

### Что за `body: 42` в файле ответа?

Количество символов тела. Блок `internet-core` сверяет длину при чтении: расхождение означает неполный файл, ответ перечитывается.

### Зачем nonce, если есть номер запроса?

Номер начинается с единицы после перезагрузки скрипта. Nonce делает имя файла уникальным, и устаревший ответ не может быть прочитан как свежий.

### Можно ли принять входящий вебхук?

Нет — только исходящие запросы. Для приёма сообщений (Telegram) используется опрос `getUpdates`.
