# Внутреннее устройство

Разбор моста для разработчиков: что происходит внутри `nursultan_bridge.py`, почему устроено именно так и как безопасно расширить.

## Жизненный цикл запроса

```
скрипт                     мост                          сеть
  |                          |                            |
  | netSend → net.req        |                            |
  |                          | опрос MCP (каждые pollMs)  |
  |                          | чтение settings скриптов   |
  |                          | разбор конверта            |
  |                          | проверки (allowlist и т.д.)|
  |                          | HTTPS GET/POST/... --------→|
  |                          |                            |
  |                          | ←------------------------- ответ
  |                          | jsonpath (по директиве)    |
  |                          | os.replace → .env файл     |
  | assets.text ← файл       |                            |
  | netCode, netBody         |                            |
```

Один поток, без `Thread` и `asyncio`: мост последовательно выполняет опрос, разбор, запрос и запись. Один медленный запрос задерживает остальные — поэтому таймаут обязателен, а лимит `maxTimeoutSec` (по умолчанию 60 с) не даёт циклу зависнуть навсегда.

## Цикл моста

Каркас главного цикла (фрагмент `nursultan_bridge.py`):

```kotlin
// упрощённо; полный код — в bridge/nursultan_bridge.py
while true:
    scripts = mcp.call("scripts_list")           // список скриптов и их настройки
    for script in scripts:
        raw = find(scripts, "net.req")           // значение входа net.req
        if raw and sha1(script.id + raw) not in seen:
            seen.add(sha1(script.id + raw))
            handle(raw, script)                  // разбор, запрос, запись ответа
    sleep(pollMs / 1000)
```

| Шаг | Что делает | Отказоустойчивость |
| --- | --- | --- |
| `scripts_list` | один MCP-вызов на цикл, возвращает все скрипты сразу | сбой сети: ошибка в лог, следующий цикл через 30 с |
| поиск `net.req` | ищет запись с ключом `net.req` в списке `settings` | ключа нет: пропуск, это норма |
| дедупликация | `sha1(scriptId + "\n" + значение)` в `stateFile` | повторное значение не выполняется дважды |
| `handle` | разбор конверта → проверки → запрос → запись | любая ошибка → ответ `code 0` со скрипту |

## Разбор конверта

Запрос — текст, а не JSON: в песочнице JSON нет, а текст скрипт и мост читают одинаково.

```text
NETREQ 3                            ← баннер и номер; номер задаёт скрипт
GET https://api.example.com/v1      ← метод и URL, одна строка
nonce: f47ac10b58cc                ← обязателен: имя файла и защита от дублей
timeout: 15                         ← необязательно, секунды
jsonpath: data.0.value              ← необязательно: вырезать поле
keyref: gemini                      ← необязательно: имя ключа из secrets
header: Accept: application/json    ← необязательно, повторяется

                                   ← пустая строка: конец шапки
{"query":"москва"}                  ← тело, может быть многострочным
```

Правила разбора:

| Правило | Поведение |
| --- | --- |
| первая строка | обязана начинаться с `NETREQ `, дальше число |
| вторая строка | `МЕТОД URL`, метод из белого списка, URL без пробелов |
| шапка | директива `ключ: значение` на строку; неизвестная директива — ошибка |
| пустая строка | конец шапки, всё после неё — тело |
| обрезка пробелов | значения директив читаются `.strip()`, тело — как есть |

## Движок jsonpath

Скрипт не парсит JSON — поэтому мост вырезает поле сам. Путь — точечная последовательность, числа индексы массивов:

```text
candidates.0.content.parts.0.text
```

Алгоритм:

```python
# упрощённо
data = json.loads(body)                # тело — валидный JSON, иначе ошибка
for part in path.split("."):
    if part.isdigit():                 # индекс массива
        data = data[int(part)]
    else:                              # ключ объекта
        data = data[part]
# строка уходит как есть; число, массив, объект, null — как JSON-текст
```

| Ситуация | Результат в файле |
| --- | --- |
| путь найден, значение — строка | текст значения |
| путь найден, значение — число/объект/массив/`null` | JSON-текст |
| путь не найден | `code 0`, текст `jsonpath: ключ не найден: ...` |
| тело не JSON | `code 0`, текст `jsonpath: невалидный JSON: ...` |

## Атомарная запись ответа

Скрипт читает файл в тике: если файл дописывается в этот момент, он увидит обрезанное тело. Поэтому запись двухфазная:

```python
tmp = resp_path + ".tmp"
with open(tmp, "w", encoding="utf-8") as f:
    f.write(f"NETRESP {id}\n{code}\nbody: {len(body)}\n{body}")
os.replace(tmp, resp_path)            # атомарно: файл появляется целиком
```

`os.replace` на Windows и Linux атомарен в пределах одной файловой системы: читатель либо видит старую версию, либо новую целиком.

## Формат файла ответа

```text
NETRESP 3              ← номер из запроса
200                    ← HTTP-статус; 0 — ошибка моста
body: 42               ← длина тела в символах, для проверки целостности
{...}                  ← тело: текст или результат jsonpath
```

Длина в строке `body:` — контрольная: блок `internet-core` сверяет её с прочитанным текстом и при расхождении считает ответ неполным.

## Дедупликация и nonce

| Механизм | Зачем |
| --- | --- |
| `sha1(scriptId + "\n" + значение net.req)` в `stateFile` | одно значение слота не выполняется дважды |
| `nonce` в имени файла | каждая отправка получает новый файл; старый ответ не читается как новый |
| счётчик `id` в скрипте | номер запроса для сверки `NETRESP` |

Nonce обязателен: после перезагрузки скрипта счётчик обнуляется, и без nonce файл `net-1-...` от прошлой жизни мог бы быть прочитан как свежий ответ.

## Очистка

```python
# при старте и каждый час
for path in glob("scripts/assets/_net/resp/**/net-*.env"):
    if age_hours(path) > cleanAfterHours:    # 24 по умолчанию
        os.remove(path)
```

Скрипт читает файл сразу после отправки, поэтому удаление старых файлов безопасно: недочитанный ответ устарел, запрос отправится заново.

## Коды ошибок

Скрипт видит `netCode = 0` и текст ошибки в `netBody`. Источники:

| Префикс текста | Источник |
| --- | --- |
| `конверт: ...` | разбор запроса: баннер, метод, URL, директивы |
| `ключ ... не найден` | `keyref` отсутствует в `secrets` |
| `{{KEY}} в запросе, но keyref отсутствует` | в URL/заголовке/теле есть подстановка, директивы нет |
| `хост ... не входит в allowlist` | проверка allowlist |
| `хост ... ведёт на приватную сеть` | проверка IP-адресов |
| `редирект ... отклонён` | редирект на нарушивший хост |
| `тело больше N байт` | превышен `maxBodyBytes` |
| `timeout after Ns` | таймаут запроса |
| `jsonpath: ...` | движок вырезания полей |
| `http: ...` | сеть: DNS, соединение, TLS |

Все они пишутся в `requestLog` строкой вида:

```text
req id=7 script=Погода GET api.example.com -> 0 15034ms err: timeout after 15s
```

## Расширение протокола

Как добавить свою директиву (пример — `useragent:`):

| Шаг | Где | Что |
| --- | --- | --- |
| 1 | `nursultan_bridge.py`, разбор шапки | принять ключ `useragent`, сохранить в запрос |
| 2 | `nursultan_bridge.py`, выполнение | применить значение к `Request` |
| 3 | `net-core.kts`, `netSend` | добавить параметр и строку `useragent: ...` в конверт |
| 4 | `docs/protocol.md` | описать директиву в таблице |
| 5 | `bridge.json`, `proto` | поднять версию протокола, если изменение несовместимо |

Совместимость: новые директивы необязательные, старый мост отклоняет неизвестные — поэтому сначала обновляют мост, потом скрипты.

## Свойства процесса

| Свойство | Значение |
| --- | --- |
| потоков | один, главный цикл |
| память | константная, тело ответа — до `maxBodyBytes` |
| права | обычные, без администратора |
| сеть | только исходящие HTTP/HTTPS |
| файлы | `bridge.json` (чтение), `requests.log`, `stateFile`, `assets/_net/resp/` |
| ресурсы | CPU пренебрежимо мало: ожидание — `sleep` |
